# 基于 EG4S20 的轨交站厅多模态显示与确定性应急切换系统

> 交稿前删除本段。本稿不写单位与姓名。插图只给绘制说明，照片只给拍摄说明。片源内部尺寸低于 640×480 的数字不写入正文。800×600 只作为解码器可接受的源图规格；板上是否已通过，以第 3.3 节实测栏为准，未测项不写成已测。

## 摘要

轨交站厅信息屏同时要播放海报、短视频和广播，又要在火警或人工急停时尽快换成疏散画面。若切换依赖操作系统调度或临时读卡，延迟和失败点都不好界定。本文在安路 EG4S20BG256 上实现一套纯硬件显示终端：HDMI 固定输出 640×480@60 Hz，TF 卡中的 24 位无压缩 BMP 经校验后写入片外 SDRAM，视频在写入同一套帧缓存前重建为 640×480。日常画面使用双缓冲，只在场同步沿交换显示页，避免写出半帧就被读出。

音频与画面共用这颗 SDRAM。视频行、场消隐留下的空档被用来突发读取 48 kHz、16 bit PCM。待机时循环播放与当前海报对应的短乐段；红外传感器触发后改为五段进站播报，播完再回到乐段。海报切换时清空音频 FIFO 并跳到新乐段起点，避免两段波形硬接产生冲击声，因此切图瞬间会有短暂静音。

应急通道不临时读卡。疏散画面事先写入独立帧区。温度升幅、外接开关量和长按按键均可置位应急。置位后，当前 SD 读事务被中止，下一场同步沿改为显示该帧区，同时由片内扫频发生器驱动板载蜂鸣器和 HDMI 音频。设计上，从触发到画面切出不超过一个场周期，60 Hz 时为 16.7 ms。示波器核对留在第 3.3 节，未完成的记录不记入本文已测数据。

拨码开关 SW[3:0] 选择 16 个调节量，旋转编码器改变当前量，正常页与应急页各有一套参数。色彩通路按灰度差做饱和度，再做对比度、亮度和色调；几何通路做缩放、平移和适配。工程用 Tang Dynasty 6.2.1（版本号 V6.2.168116）实现。布局布线后 LUT 18816/19600（96.00%），BRAM 61/64（95.31%），DSP 28/29（96.55%），建立时间裕量 +0.151 ns，保持时间裕量 +0.024 ns。

## 第一部分  作品概述

### 1.1 功能与特性

终端有四条同时存在的功能，而不是四套互斥演示。

日常态从 TF 卡读取 640×480、24 位、无压缩 BMP，支持自动轮播和按键换页。每张海报对应一段循环短乐，画面底部用音频幅度画包络。红外输入有效后，短乐让给五段进站播报，画面随播报阶段更换；播报结束且红外撤销后，回到海报和短乐。

SW[3:0] 与编码器在不重新读卡的情况下调节亮度、对比度、色调、饱和度、缩放、平移、适配、图层不透明度、混合、滚动速度、位置、过渡方式、过渡时长、轮播节拍和方向。正常页与应急页参数分开保存。

应急态显示预先写入的疏散画面。温度相对基线升高约 2 ℃、外接低电平开关量或指定按键长按都可以进入。进入后，蜂鸣器与 HDMI 同时输出约 520 Hz 至 1180 Hz 的往复扫频。返回日常态后，海报、视频和音频按原状态继续。

### 1.2 应用领域

第一种用途是站厅综合信息屏。平时轮播通知和短乐，列车接近时改播进站词和对应画面，异常时改播疏散页。画面切换点落在场同步沿上，延迟上界可以用场周期写清，便于和运行时间表、广播词对齐。

第二种用途是地下公共空间的疏散指示。烟感、温感和人工按钮并到同一应急输入后，显示内容不再依赖主机进程是否还在响应。本文外接开关量为低电平有效，并做了约 20 ms 消抖；未接入的传感器不改变这项逻辑。

第三种用途是同分辨率下的本地显示终端。输出时序、帧缓存和按键调节都不绑定站厅文案。更换 TF 卡中的 BMP 和 WAV 后，几何调节、双缓冲和应急切页仍然可用。输出分辨率保持 640×480，不在本文范围内改成更高的 HDMI 时序。

【图1-2 绘制说明】三个方框横排：站厅信息屏、疏散指示、本地显示终端。每个方框下只写一行约束：“输出 640×480@60 Hz”。三个方框用虚线回到中间的 FPGA 方块。

### 1.3 主要技术特点

片外 SDRAM 同时承担海报双缓冲、应急帧、进站画面和 PCM。读视频的空档插入定长音频突发，写海报的优先级高于这段突发，避免音频把正在写出的行撕开。

BMP 解码接受 640×480 和 800×600 两种 24 位无压缩、自下而上文件。800×600 在写入帧缓存前按行抽样到 640×480，显示时序不变。演示用海报按 640×480 制作。视频无论片内编码尺寸如何，重建结果都是 640×480 帧；日常主视窗取其中 520×292，应急时使用整帧。520×292 的宽高比约为 16:9，与进站视频素材一致。

色彩和几何在像素时钟域完成，不回写 TF 卡。应急置位时，SD 控制器结束当前扇区事务并清空写 FIFO，显示指针在随后的场同步沿改到应急帧。音频输出从 PCM 改为扫频发生器，不占用 SD 带宽。

### 1.5 主要创新点

1. 音频不另备存储器。PCM 插在视频访存空隙中读取，海报页、进站播报和扫频共用 HDMI 音频时隙，扫频时不再读卡。
2. 疏散帧在进入应急前已经写好。触发后只改显示页并中止未完成的读卡，切换上界由场周期决定，而不是由文件长度决定。
3. 800×600 源图归一化到既有 640×480 帧缓存和 HDMI 时序，调节参数不随源图尺寸增加一套数据通路。

### 1.6 设计流程

先确定输出只能是 640×480@60 Hz，再分配 SDRAM 页、SD 事务和音频时隙。海报、播报和短乐在 PC 上转成约定格式，并检查 TF 卡上的簇是否连续。RTL 完成后用 Tang Dynasty 6.2.1 综合、布局布线和生成比特流；时序不满足时不保留该比特流。上板按第 3.3 节的条目记录出图、换页、进站、应急和返回。

## 第二部分  系统组成及功能说明

### 2.1 整体介绍

系统分成七个时钟域上的功能块，数据最终都落到 HDMI。50 MHz 板载时钟进入三颗 PLL：系统 PLL 给出 SD 侧 62.5 MHz、存储侧 50 MHz 以及约 162° 相移的 SDRAM 时钟；视频 PLL 给出 25 MHz 像素时钟和 125 MHz 的五倍串行时钟；音频 PLL 给出 12.288 MHz，对应 48 kHz×256。

TF 卡控制器在 62.5 MHz 域扫描根目录，识别 BMP、WAV 和进站视频文件，按扇区把样本送进归一化或重建模块，再经异步 FIFO 写入 SDRAM。25 MHz 域只读当前显示页，做几何取样、色彩和站厅叠加，然后送入 HDMI 1.4b 发送核。12.288 MHz 域从 SDRAM 取 PCM 或在应急时改接扫频样本，打包进 HDMI 音频包。50 MHz 域处理按键、编码器、温度、红外、开关量和串口。跨域信号用邮箱或双级同步，帧描述在场同步之后锁存，避免显示域读到写了一半的控制字。

### 2.2 硬件系统介绍

#### 2.2.1 硬件整体介绍

硬件以 EG4S20BG256 开发板为中心，不另做主控板。板上使用 TF 卡座、HDMI、按键、拨码开关、旋转编码器和蜂鸣器。片外 SDRAM 按 2M×32 bit 地址空间使用，海报、应急帧、进站画面和 PCM 分占不同区间，区间在编译期固定。

显示器接 HDMI。要求显示器以 640×480、4:3 或点对点方式显示。若显示器把输入拉成 16:9，顶栏和侧栏会一起变扁，这是显示器比例设置，不是帧缓存尺寸变化。日常主视窗本身按约 16:9 取景，应急页才铺满 640×480。

温度与红外接在排针 J1。开关量与两根示波器观察脚按约束文件接在 J4，管脚见表 2-2。开关量可以并联多个低电平有效模块，任一模块拉低即满足应急条件。未使用的排针保持设计中的默认电平，不在本文中改作总线。

页地址按 32 bit 字计，一个字对应一个像素或一个 PCM 采样。页 A 从 0 起，页 B 从 307200 起，应急页从 614400 起。音频区从 983040 起，长度 960000 个采样，约等于 48 kHz 单声道 20 s。应急页结束到音频区之间空出 61440 个字。图 2-5 标这四个起点即可。

写海报时，800×600 的行先进入行缓存，再按 4 个源行对应 5 个输出行的关系抽样到 640 点宽。640×480 文件跳过这次抽样。两种文件写入帧缓存后的长度都是 640×480。视频样本经四行缓存和双线性插值写成同样大小的帧，随后在显示域按 16:9 主视窗取样。因此 HDMI 时序、OSD 坐标和帧长都不随源文件变化。

应急置位后，若 SD 仍在读扇区，控制逻辑结束这次读请求并清空写 FIFO，避免半行留在帧缓存里。已经写完的应急页不被这次中止改写。显示域看到应急标志后，在场同步边界改读指针。最坏情况是触发刚刚错过本场的决策点，于是要等到下一场，间隔不超过 16.7 ms。

### 2.3 逻辑与上位机

#### 2.3.1 整体介绍

片上逻辑集中在顶层 `top`。TF 与帧缓存由 `sd_card_bmp` 调度，其下为扇区读、BMP/视频解析、归一化、双线性重建和 SDRAM 读写。显示域包括时序发生、几何取样、色彩、站厅字符和 HDMI 发送。音频域包括 PCM FIFO、进站/短乐地址和扫频发生器。控制域包括消抖、16 个调节量、温度判断和串口。

PC 不参与实时显示。PC 上的工作是：把 PNG 转成约定 BMP，把播报和短乐放进同一个 WAV，写卡时保持文件连续，并用只读方式复核簇链。串口在运行时可选，用于看状态码和音量，不作为画面通路的一部分。

【图2-7 绘制说明】两列。左列“片上”，自上而下：文件扫描、帧写入、显示读出、色彩与叠加、HDMI、音频源选择。右列“PC”，三个框：图像转换、音频拼接、连续簇检查。右列用虚线指向 TF 卡，TF 卡再用实线进入左列。串口从左列用虚线回到 PC，标注“115200，可断开”。

资源以布局布线报告为准：LUT 18816/19600，寄存器 10348/19600，BRAM 61/64，DSP 28/29，PLL 3/4，用户 IO 54。DSP 用于插值和色彩乘法。BRAM 用于行缓存、FIFO 和字符字模。剩余 LUT、BRAM 和 DSP 都不多，因此没有把 HDMI 时序改到 640×480 以外。

#### 2.3.2 模块说明

**文件扫描与读事务。** 扫描从根目录扇区顺序进行，不依赖操作系统的目录缓存。BMP 头必须为 “BM”，位深 24，压缩字段为 0，宽高为 640×480 或 800×600。WAV 头为 RIFF/WAVE。进站视频使用工程约定的文件头，重建后进入 640×480 帧，正文不列出低于输出分辨率的内部编码尺寸。

读事务一次对应一个扇区序列。换页、进站或应急都可以请求中止。中止只结束当前读和写 FIFO，不清除已经完成的应急页，也不把扫描结果清掉。写指针和显示指针分离：后台可以写下一页，显示仍读当前页，直到场同步。

【图2-8 绘制说明】状态图。圆角框：空闲、扫描、读 BMP、读视频、读 WAV、排水/中止。扫描指向三类读。三类读都可以回到空闲。从三类读各画一条短箭头到“中止”，中止只回到空闲。旁边注：“应急页已写完则保留”。

**帧写入。** 640×480 的 BMP 按像素顺序写入当前后备页。800×600 先做行抽样，输出仍是 480 行、每行 640 点。视频重建使用四行缓存：每个输出像素在水平方向取相邻两点、垂直方向取相邻两行，插值乘法分时复用。输出坐标走完 640×480 后给出完成标志，写指针才允许在场同步时发布。

日常显示不使用整幅 640×480 作为主视窗。主视窗宽 520、高 292，起点在画面中部，宽高比约 16:9。应急时视窗改为 0 至 639、0 至 479。进站视频在写入时已铺进 640×480 存储；显示域对视频源再做一次水平或垂直修正，使 16:9 素材在 4:3 帧里不以错误比例拉伸。海报是 4:3 全幅，放进 16:9 视窗时上下会被视窗裁掉一部分，这是取景，不是文件分辨率错误。

**显示调节。** SW[3:0] 的编码与调节量一一对应，编码器每步的增量在 RTL 里写死。正常页和应急页各存一套，进入应急不会带入日常页的缩放。按住编码器旋转时只改音量，不改表 2-3 的量。

**音频。** WAV 文件为 48 kHz、16 bit、单声道。HDMI 左右声道发送同一采样。文件前部是五段播报，样点区间依次为：进站说明 0～242522，约 5.05 s；到站提示起始样点 243003，约 3.67 s；即将出站起始样点 419496，约 4.12 s；正在出站起始样点 617946，约 3.43 s；下一站起始样点 782867，约 1.59 s。演示词依次为进站说明、“科技园到了”、“即将出站”、“正在出站”和“下一站，大学城”。样点 860160 之后放置四段循环短乐，每段 24960 个样点，约 0.52 s，长度取突发对齐。待机且未进站时，按当前海报选择其中一段循环。

进站开始时地址跳到对应播报段。海报索引变化时，逻辑清空 PCM FIFO 再从新短乐起点读取。清空是为了去掉上一段残留样点，听感上就是切图时短暂停顿。停顿长度取决于 FIFO 深度和新页读入时间，本文不写成固定毫秒数。

应急有效后，音频源改为扫频。发生器在 50 MHz 上先做 256 分频，再用 9 bit 周期计数在约 520 Hz 与约 1180 Hz 之间往复，方波驱动蜂鸣器，同一控制量同步送入 HDMI。音量调节只缩放送进 HDMI 的幅度，蜂鸣器为数字开关量。

**进站与应急顺序。** 红外有效后按播报段推进画面，顺序与五段音频一致。红外撤销后进入“下一站”并回到可轮播状态。温度每约 2 s 更新一次；升幅达到约 2 ℃ 且连续两次判断成立后进入应急页。应急页可在已加载的疏散画面之间换页。长按 key3（B1）返回日常流程。初始化尚未完成时进入应急，返回后应能重新完成扫描和后续红外播报。这些顺序以源码状态机和上板清单为准，拍摄时按同一顺序操作。

## 第四部分  总结

### 4.1 可扩展之处

输出时序仍应保持 640×480@60 Hz。LUT、BRAM 和 DSP 都已超过 95%，把像素时钟改到 720p 或 1080p 会同时改变 SDRAM 带宽和 HDMI 锁相，不属于在现比特流上加功能。

可以继续用的余量在文件和输入侧。解码器已经接受 800×600 BMP，并在写帧前归一化；若第 3.3 节第 10 行失败，演示材料退回 640×480，设计说明仍可保留这一规格。开关量输入允许多个低电平器件并联，增加烟感或按钮时不必改 HDMI 通路。

音频切页时的停顿来自 FIFO 清空。若要缩短停顿，需要在不清空的情况下做交叉衰减，这会增加音频域的缓冲和状态，应单独评估时序，而不是在当前比特流上直接打开。


### 4.2 研制说明

研制过程里，有几件事边界很清楚，写进说明比写成体会更有用。

输出分辨率先被钉死。赛题材料要求画面不低于例程的 640×480，主办方也明确图片、视频和动画都按这个下限。工程若同时宣传更小的片内编码尺寸，评审时会和这条下限打架。因此正文只写 HDMI 640×480，以及写入帧缓存之后的 640×480。日常界面中的 520×292 是取景窗口，用来对齐 16:9 的进站画面，不是另一套输出时序。海报放进这个窗口会损失上下边缘，拍摄和文档都要按这个取景解释，避免把裁切说成比例错误。

存储是第二件边界。片外 SDRAM 只有一套读端口和一套写端口，海报、应急帧、进站画面和 PCM 不能各占一条物理总线。音频放在视频空档里读，是因为再增加存储器或提高存储时钟都会碰到器件和时序。短乐长度做成突发的整数倍，只是为了地址跳转时不必处理半个突发，并没有提高音质。

第三件是文件系统。FPGA 从起始扇区往后读，簇一旦断开，画面会错，而文件头仍然合法。所以写卡流程把“字节数正确”和“簇连续”分成两次检查。640×480 海报长度不变，可以原位覆盖；800×600 更长，必须重写文件后再查簇。这一步不能省。

第四件是工具版本。官方评审环境是 TD 6.2.1。更高版本里用于收紧布线的步骤，在 6.2.1 中并不等效。工程没有换版本生成比特流，而是在现版本的时序报告上处理真正失败的路径。缩放器里已经用仿真核对过的多周期路径保留；启动后不再变化的计数值也按多周期处理。最终建立裕量 +0.151 ns、保持裕量 +0.024 ns 才生成比特流。负裕量的中间结果没有拿去下载。

第五件是应急的时间账。只要切换发生在场同步沿，延迟上界就是一个场周期，与 BMP 有多大无关。前提是疏散页已经写完，并且未完成的读事务会被丢掉。若应急发生时还在读海报，中止逻辑必须清掉写 FIFO，否则下一页可能从半行开始。这个条件和“小于 16.7 ms”是一起的：只改显示指针、不清事务，上界并不成立。示波器要测的是触发沿到场同步沿，不是文件拷贝时间。

调节功能以 RTL 中的 16 个量为准。色彩是亮度、对比度、色调和饱和度，几何是缩放、平移和适配，其余是图层和轮播参数。演示脚本若写成边缘检测或浮雕，就和实现不一致。音量是编码器按住旋转，不占用这 16 个编码。

后续补测只填表 3-2 的空栏。
