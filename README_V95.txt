V95 铁路异常恢复优化：上板测试版

本次修复了检查中能复现的五类问题：
1. 第二轮寻找音频目录时卡住，初次图片扫描已完成，旧看门狗没有覆盖这个阶段。现连续6秒没有扇区进展会自动重扫；持续有数据的长扫描不会按总时长误杀。
2. WAV音频读取超时，旧逻辑只退出部分状态，未可靠取消已开始的SDRAM写入。现取消解析器、部分写入和卡事务，保留已提交画面，等待重新加载。
3. 超时与ACK/完成同一时刻到达，后续分支可能又发起读取或将未完整PCM标为ready。现超时清理拥有明确优先级。
4. 音频读完返回IDLE时多发一次启动，形成没有管理器归属的重复读取。新增结束握手保护；应急海报预加载失败时也立即取消部分写入。

5. 开机已遮挡红外，但配音尚未发现时提前进入静音演示。现在等待目录确认和配音加载完成；未完成的音频查找被复位/应急打断后会重新查找。正常照片/视频请求与初次配音初始化也保持互斥，第一张开机图片仍可先显示。

使用方法：保留现有V94配套TF卡，先PROGRAM_SRAM下载release_v95/Metro_V95.bit并复位。
视频分辨率、帧率、图片素材、五段配音、画面设置、字幕和温升阈值均沿用V94。无需重新转码或复制TF素材。
完整工程重新编译：解压整个目录后运行Build-V95.cmd；编译脚本会严格检查最终时序。
本机编译器为 Tang Dynasty V6.2.178840，目标 EG4S20BG256；另一台电脑需安装相应TD工具，编译脚本找不到时会提示填写编译器路径。
WAV总读取期限按实际时钟计算为40秒。旧常数在62.5MHz下实际是64秒，注释与实际不一致。
